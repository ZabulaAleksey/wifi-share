# WiFi Share

WiFi Share — локальное приложение для безопасного обмена файлами между компьютером и устройствами в одной Wi‑Fi сети. Компьютер запускает HTTP-сервер, а телефоны, планшеты, телевизоры и другие компьютеры открывают адаптивный интерфейс по локальному URL или QR-коду.

## Цели первой версии

- Просмотр дерева разрешённой общей папки.
- Загрузка и скачивание файлов.
- Создание папок, переименование, редактирование небольших текстовых файлов и безопасное удаление.
- Просмотр изображений и воспроизведение аудио/видео с перемоткой.
- Только один активный медиаплеер среди вкладок одного браузера.
- Иконки по типам файлов и кэшируемые миниатюры для медиа.
- Запуск без внешнего облака и без передачи данных в интернет.

## ADR-001: Go для локального сервера

**Решение:** сервер реализуется на Go поверх стандартного `net/http`.

**Причины:**

- один компактный исполняемый файл;
- низкое потребление памяти;
- хорошие характеристики потоковой передачи больших файлов;
- стандартный `http.ServeContent` поддерживает HTTP Range, ETag и условные запросы;
- простой выпуск под Windows, macOS и Linux.

Сервер слушает настраиваемый адрес, по умолчанию `:8080`, и получает только одну явно выбранную общую папку. Произвольный доступ к диску запрещён.

### Настройка общей папки

Путь к файлам является параметром запуска, а не частью исходного кода. Он передаётся через CLI-флаг `-root`:

```powershell
.\wifi-share.exe -root "D:\Media"
```

Без флага сервер использует `.\shared` относительно текущего рабочего каталога. Параметр объявлен в `cmd/wifi-share/main.go` и передаётся в `app.Config.ShareDir`. При запуске сервер вычисляет абсолютный нормализованный путь и проверяет каждый файловый запрос относительно этого корня.

Связанные параметры: `-data` задаёт приватные служебные данные, `-web` — production-сборку интерфейса, `-addr` — адрес и порт сервера.

Каталог `-data` нельзя размещать внутри `-root`, иначе база, корзина и будущий кэш миниатюр могут стать доступны клиентам.

## ADR-002: React, TypeScript и Vite для интерфейса

**Решение:** клиент создаётся на React и TypeScript, собирается Vite.

React подходит для файлового менеджера с несколькими независимыми состояниями: навигация, загрузки, просмотр, плеер и фоновые обновления. TypeScript фиксирует контракты API, а Vite обеспечивает короткий цикл разработки.

Для серверного состояния используется TanStack Query. Локальное состояние остаётся внутри React-компонентов; отдельный глобальный store добавляется только при появлении подтверждённой необходимости.

## ADR-003: REST API и непрозрачные ID

Клиент не отправляет абсолютные пути. Сервер кодирует относительный путь в непрозрачный идентификатор, повторно проверяет итоговый путь и не допускает выход за общую директорию или переход по внешней символической ссылке.

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/api/files?parent={id}` | Содержимое папки |
| `POST` | `/api/files/{id}/upload` | Multipart-загрузка |
| `POST` | `/api/files/{id}/folders` | Создание папки |
| `GET` | `/api/files/{id}/content` | Просмотр, скачивание, Range |
| `PUT` | `/api/files/{id}/content` | Замена содержимого небольшого файла |
| `PATCH` | `/api/files/{id}` | Переименование |
| `DELETE` | `/api/files/{id}` | Перемещение в системную корзину Windows |

Удаление обратимо: на Windows объект отправляется в системную корзину через `SHFileOperationW` с `FOF_ALLOWUNDO`. Собственная корзина приложения не создаётся.

## ADR-004: SQLite для локальных метаданных

SQLite хранит настройки, журнал операций, токены доступа, кэш метаданных и будущие записи корзины. Файлы не помещаются в базу данных. Используется WAL-режим, чтобы чтение состояния не блокировало короткие записи аудита.

## ADR-005: Vidstack как единая медиаплатформа

Vidstack используется для аудио и видео. Он предоставляет единый API, доступные элементы управления, мобильные жесты, полноэкранный режим, Picture-in-Picture, субтитры, AirPlay/Google Cast и настраиваемые layouts.

Сервер обязан поддерживать `Range` и корректный `Content-Type`, иначе перемотка и продолжение воспроизведения больших файлов будут ненадёжны.

## ADR-006: единственный плеер между вкладками

Каждая вкладка создаёт уникальный `tabId` и подключается к каналу `wifi-share-media` через `BroadcastChannel`. Перед началом воспроизведения вкладка публикует событие `playing`; остальные вкладки ставят свои плееры на паузу.

`Web Locks API` не является основным механизмом, поскольку при открытии по локальному IP через HTTP браузер может не считать контекст безопасным. Если в будущем появится локальный HTTPS, Web Locks можно добавить как дополнительную строгую блокировку.

Ограничение распространяется на вкладки одного браузерного профиля. Для единственного плеера среди всех устройств потребуется серверная аренда через WebSocket.

## ADR-007: миниатюры и иконки

Файлы получают иконку по MIME и расширению. Для изображений сервер асинхронно создаёт уменьшенный WebP, для видео FFmpeg извлекает репрезентативный кадр, для аудио извлекается встроенная обложка.

Ключ кэша миниатюр:

```text
sha256(relativePath + fileSize + modificationTime + thumbnailProfile)
```

Кэш хранится вне общей папки. Ошибка генерации миниатюры не должна мешать скачиванию оригинала. В начальном каркасе реализованы типовые иконки; FFmpeg-конвейер входит в следующий этап.

## ADR-008: безопасность по умолчанию

- Доступна только явно выбранная директория.
- Проверяются `..`, абсолютные пути и символические ссылки.
- Мутации требуют авторизованной HttpOnly-сессии.
- Для подключения нового устройства будет использоваться короткоживущий PIN или QR-токен.
- Режим «только чтение» включается независимо для каждой общей папки.
- Рекомендуемый режим сети — private/home; публикация порта в интернет не поддерживается.
- Запись файла выполняется через временный файл и атомарное переименование.
- Редактирование ограничено текстовыми файлами небольшого размера.
- Внешние запросы и telemetry отсутствуют.

## Целевая структура

```text
wifi-share/
├── cmd/wifi-share/        # точка входа Go
├── internal/app/          # HTTP API, файловая безопасность, SQLite
├── web/                   # React/TypeScript/Vite
├── shared/                # пример общей папки, не коммитится
├── data/                  # БД, корзина, миниатюры, не коммитится
└── ARCHITECTURE.mdx       # архитектурные решения
```

## План развития

1. Базовый файловый API, адаптивный интерфейс и общий медиаплеер.
2. Миниатюры FFmpeg/WebP, просмотр изображений и текстовый редактор.
3. Pairing по PIN/QR, права read/write и список подключённых устройств.
4. WebSocket-события, наблюдение за файловой системой и прогресс операций.
5. Возобновляемые загрузки, ZIP на лету и восстановление из корзины.
6. PWA и desktop shell с tray-меню и автоматическим обнаружением LAN-адреса.


## ADR-009: локальный пароль и разделение прав

Настройки запуска и пароль хранятся в `config.local.json`. Файл исключён через `.gitignore`; `config.example.json` содержит только структуру без рабочего секрета.

Чтение списка, открытие и воспроизведение доступны без входа. `POST`, `PUT`, `PATCH` и `DELETE` файлового API проходят через серверный middleware авторизации. После правильного пароля сервер создаёт криптографически случайную 24-часовую сессию и устанавливает `HttpOnly`/`SameSite=Strict` cookie. Сравнение пароля выполняется в постоянное время.

Сессии намеренно хранятся в памяти: перезапуск `.exe` завершает полный доступ на подключённых устройствах. Это безопасное поведение по умолчанию для локального сервиса.

## ADR-010: наблюдаемый прогресс загрузки

Каждый файл загружается отдельным multipart-запросом через `XMLHttpRequest`. События `upload.progress` показывают переданные байты и процент для каждого файла. Сервер повторно проверяет авторизацию и имя файла независимо для каждого запроса.
## ADR-011: системный трей и динамическая папка

Windows-сборка использует getlantern/systray. HTTP-сервер работает в фоновой goroutine, а tray управляет открытием браузера, URL, config.local.json, общей папкой и корректным завершением. Смена папки защищена RWMutex и применяется без перезапуска.

## ADR-012: плейлист текущей папки

Очередь строится на клиенте из аудио- и видеофайлов текущего листинга. Событие ended выбирает следующий элемент; после последнего элемента очередь останавливается.
